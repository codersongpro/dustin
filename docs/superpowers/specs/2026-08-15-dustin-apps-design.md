# Dustin Apps 설계

## 1. 목적

`codersongpro` GitHub 계정에서 실제로 배포된 공개 웹 앱을 자동으로 모아 보여주는 단일 페이지 웹 앱을 만든다. 방문자는 앱 이름, 간단한 소개, 배포 주소를 확인하고 각 앱을 바로 열 수 있다.

배포 목표는 Vercel Production이며 희망 주소는 `https://dustin.vercel.app`이다. `.vercel.app` 주소는 선착순으로 할당되므로 실제 프로젝트 생성 시 사용 가능 여부를 최종 확인한다.

## 2. 공개 범위와 등록 규칙

- GitHub 사용자: `codersongpro`
- 공개 저장소만 조회한다.
- 보관된 저장소와 포크 저장소는 제외한다.
- GitHub 저장소의 `Website` 값이 유효한 `http://` 또는 `https://` 주소인 경우에만 배포 앱으로 등록한다.
- 앱 이름은 저장소명, 소개는 저장소 `Description`, 배포 주소는 `Website`를 사용한다.
- `Description`이 없으면 `소개가 아직 등록되지 않았습니다`를 표시한다.
- 목록은 저장소의 최근 수정 시각을 기준으로 내림차순 정렬한다.

새 앱을 자동 등록하는 운영 절차는 다음 두 단계다.

1. 앱을 공개 GitHub 저장소에 업로드하고 배포한다.
2. 저장소의 `Description`과 `Website`를 입력한다.

위 조건을 만족한 앱은 최대 1시간 안에 목록에 반영된다.

## 3. 기술 구조

- Next.js App Router와 TypeScript를 사용한다.
- Vercel에 배포하고 Next.js의 시간 기반 재검증 기능으로 GitHub 응답을 3,600초 동안 캐시한다.
- 서버에서 GitHub의 공개 사용자 저장소 API를 호출한다.
- GitHub 인증 토큰과 별도 데이터베이스는 사용하지 않는다.
- 클라이언트에는 정규화된 앱 데이터만 전달한다.

정규화된 앱 데이터는 아래 필드로 제한한다.

- `name`: 저장소명
- `description`: 저장소 설명 또는 기본 안내 문구
- `homepage`: 검증된 배포 주소
- `repositoryUrl`: 공개 저장소 주소
- `updatedAt`: 정렬용 최근 수정 시각

## 4. 데이터 흐름

1. 방문자가 Dustin Apps 페이지를 요청한다.
2. 서버는 유효한 1시간 캐시가 있으면 즉시 사용한다.
3. 캐시가 없거나 재검증 시점이면 GitHub 공개 API에서 `codersongpro`의 저장소를 최대 100개 조회한다.
4. 공개, 비보관, 비포크, 유효한 `Website` 조건을 적용한다.
5. 허용한 다섯 필드만 정규화하고 최근 수정 순으로 정렬한다.
6. 서버가 카드 목록 HTML을 생성해 반환한다.
7. 갱신 요청이 실패했지만 이전 캐시가 있으면 기존 목록을 계속 제공한다.

## 5. 개인정보와 보안

- 이메일, 실명, 위치, 프로필 사진, 커밋 작성자, 팔로워 정보는 수집·저장·표시하지 않는다.
- 비공개 저장소의 이름과 메타데이터를 요청하거나 노출하지 않는다.
- 공개 계정명 `codersongpro`는 GitHub API 조회 설정에만 사용한다.
- 외부 주소는 URL 파서로 검증하고 `http:`과 `https:` 프로토콜만 허용한다.
- GitHub의 설명을 일반 텍스트로 렌더링하며 임의 HTML을 삽입하지 않는다.
- 새 창으로 여는 외부 링크에는 `noopener noreferrer`를 적용한다.
- 서버 응답이나 오류 메시지에 불필요한 GitHub 원본 데이터가 포함되지 않게 한다.

## 6. 화면 설계

페이지 상단에는 `Dustin Apps` 제목과 `직접 만든 웹 앱을 한곳에서 만나보세요`라는 소개를 배치한다. 본문은 여백이 넉넉한 카드 그리드로 구성한다.

- 데스크톱: 3열
- 태블릿: 2열
- 모바일: 1열
- 밝은 중성 배경, 흰색 카드, 짙은 본문 색상, 절제된 포인트 색상
- 카드에는 앱 이름, 두 줄 이내 소개, 짧게 표시한 주소, `앱 열기` 버튼을 배치
- 마우스를 올리면 카드가 미세하게 상승하고, 키보드 포커스 상태를 명확하게 표시
- 첫 버전에서는 검색, 분류, 관리자 화면, 앱 미리보기 이미지를 제외

## 7. 오류와 빈 상태

- GitHub 갱신 실패 시 이전 캐시가 있으면 기존 목록을 제공한다.
- 최초 요청에서 GitHub 조회가 실패하면 잠시 후 다시 시도해 달라는 안내를 표시한다.
- 조건에 맞는 앱이 하나도 없으면 GitHub 저장소의 `Website` 등록 방법을 안내한다.
- 한 저장소의 `Website`가 잘못되었으면 해당 저장소만 제외하고 나머지 앱은 정상 표시한다.
- 소개가 비어 있는 앱은 기본 안내 문구로 대체한다.

## 8. 검증 기준

자동화 테스트로 다음 동작을 검증한다.

- 공개 저장소이면서 유효한 `Website`가 있는 항목만 포함
- 비공개, 보관, 포크, 잘못된 URL 항목 제외
- 개인정보 필드가 정규화 결과에 포함되지 않음
- 소개 기본값과 최근 수정 순 정렬
- 정상 목록, 빈 목록, GitHub 오류 화면

수동 및 배포 검증으로 다음을 확인한다.

- 모바일, 태블릿, 데스크톱 레이아웃
- 키보드 탐색과 포커스 표시
- 앱 링크의 실제 접속과 안전한 새 창 열기
- 프로덕션 빌드 성공
- Vercel Production 배포 성공
- 가능할 경우 `https://dustin.vercel.app` 연결과 실제 HTTP 응답

## 9. 완료 조건

- 승인된 화면과 필터 규칙이 구현되어 있다.
- 자동화 테스트와 프로덕션 빌드가 통과한다.
- 공개 페이지와 네트워크 응답에서 개인정보 및 비공개 저장소 정보가 확인되지 않는다.
- GitHub 저장소의 `Description`과 `Website` 변경이 최대 1시간 안에 반영된다.
- Vercel Production URL에서 목록과 외부 앱 링크가 정상 작동한다.
